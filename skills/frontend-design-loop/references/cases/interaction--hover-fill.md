# HoverFill 悬浮填充

`interaction/hover-fill` · ORIGINAL_PRACTICE · 上游复核状态 pending

**来源定位**　[悬浮填充 HoverFill](https://wxad.design/abc/springen) · [共享背景](https://wxad.design/abc/springen) · [作为轻量卡片](https://wxad.design/abc/springen) · [作为轻量输入框](https://wxad.design/abc/springen) · [标签页 Tabs](https://wxad.design/abc/springen)

**案例或原则（UI Lab 的来源笔记）**　指针进入时以轻微缩放和中心偏移回应方向。同一父元素内相邻条目移动共享底色。Tabs 案例移动的是选中指示器和文字裁切层。

**原条目中的触发场景**　指针进入可悬停条目，或在共享容器内移到相邻条目。

**为什么这样做**　短距离移动共享背景，使反馈跟着指针从一个目标转至另一个目标。初次进入的轻微偏移交代方向。

**实际要解决的问题**　连续掠过一组同级控件时，各自显隐的底色割裂控件之间的关系。

**预期效果**　用户仍能识别当前目标，同时感到这些操作属于一组。

## UI Lab 扩写与适用边界

**适用条件**　相邻同级按钮、等价卡片或轻量输入控件。

**前提**　独立的焦点和选中状态。

**代价**　隐式按 DOM 父级分组可能覆盖无关控件。

**库中反例或不适用场景**　主次或危险操作混排、独立卡片、无悬停输入。

**实现成本**　需要管理进入、跨项、出组、取消，并处理目标几何变化。

**结构限制**　同父级且语义同组，或另行设计显式分组。

**性能风险**　高频重新测量目标可能引发布局开销。

**无障碍注意项**　背景层不可接管焦点、指针或触屏反馈。
