# 用不同响应速度表现拖尾

`principle/map-wxad-trail-3` · ORIGINAL_PRACTICE · 上游复核状态 pending

**来源定位**　[不是 2 个元素，而是同个元素的 2 个端点](https://wxad.design/abc/trail)

**案例或原则（UI Lab 的来源笔记）**　示例以快速近端和迟缓远端塑造同一本体的惯性拉伸。

**为什么这样做**　把两个伪端点映射到同一视觉层，跟手端响应优先，离开时归静态形状。

## UI Lab 扩写与适用边界

**适用条件**　具有两端、且允许轻量形变的装饰线或指示物

**如何应用**　把两个伪端点映射到同一视觉层，跟手端响应优先，离开时归静态形状。

**代价**　延迟端过慢会使轨迹显得黏滞，访问状态仍需直接。

**库中反例或不适用场景**　范围控制拖动时故意让真正的滑块值滞后于用户输入。
